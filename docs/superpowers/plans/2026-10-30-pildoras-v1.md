# Píldoras v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sitio Astro estático "Píldoras" con datos de ejemplo, búsqueda, fichas por marca, páginas de DCI y criterios, publicado en GitHub Pages; listo para cambiar a Supabase sin tocar las páginas.

**Architecture:** Astro genera todo el HTML en build a partir de `src/lib/datos.ts`, que hoy lee JSON de ejemplo y mañana las vistas públicas de Supabase. El buscador es un `<script>` cliente detrás de la interfaz `buscar(q)`, con implementación local (maqueta) o RPC `buscar_medicamentos` (si existen las variables públicas de Supabase). GitHub Actions construye, prueba y despliega.

**Tech Stack:** Astro 5 (estático, TypeScript estricto), Vitest, Playwright, `@supabase/supabase-js` 2, `@astrojs/sitemap`, `@fontsource/bricolage-grotesque`, `@fontsource/atkinson-hyperlegible`, Node 22.

**Spec:** `docs/superpowers/specs/2026-10-30-pildoras-v1-design.md` (y la dirección visual en `docs/superpowers/specs/2026-10-30-pildoras-diseno-visual.md`, maqueta en `docs/diseno/direcciones-de-diseno.html`, pestaña C).

## Global Constraints

- Idioma de la interfaz: español de Chile, trato de "usted".
- Veredictos: `se_puede_partir` / `no_debe_partir` / `no_puede_partir`; sellos "Sí, se puede partir" / "No se debe partir" / "No se puede partir"; etiquetas "Se puede partir" / "No se debe partir" / "No se puede partir"; colores `#157a55` / `#c42c2c` / `#4a5b63`. Siempre ícono + texto + color.
- Paleta: marca `#0b6f68`, tinta `#14302d`, fondo `#f3f7f6`, tarjeta `#ffffff`, alvéolo `#e2ecea`, botón contacto `#7fe0c4` sobre tinta.
- Tipografía: Bricolage Grotesque 800 con espaciado negativo para títulos; Atkinson Hyperlegible base 16,5 px para texto.
- Rótulo del dibujo exacto: "Imagen ilustrativa, no a escala".
- Sin precios, ofertas ni llamados a comprar medicamentos.
- Todos los enlaces internos pasan por `url()` (Task 1); nunca `href="/..."` escrito a mano.
- `site`/`base` desde env `SITIO_URL` (por defecto `https://sebastianignacioromero-byte.github.io`) y `SITIO_BASE` (por defecto `/PILDORAS`).
- Mientras `DATOS_FUENTE` sea `ejemplo`: franja "Datos de ejemplo" visible y `noindex` en todo el sitio.
- Nunca usar ni mencionar la `service_role`; solo `PUBLIC_SUPABASE_URL` y `PUBLIC_SUPABASE_ANON_KEY`.
- Funciona y se ve bien a 375 px de ancho, sin scroll horizontal.

## Review Focus

- Consulta con tildes, mayúsculas, espacios extra o de 1 carácter → sin error; con < 2 caracteres no busca (test en Task 4).
- DCI presente en varias marcas y marca con dos DCI (asociación) → aparece en ambas páginas de DCI y sin duplicados en resultados (tests en Tasks 3 y 4).
- Ficha cuyo veredicto no coincide con su criterio, o slug repetido → la construcción falla con mensaje que nombra la ficha (test en Task 3).
- Sitio servido bajo `/PILDORAS/` → ningún enlace ni recurso roto (test Playwright en Task 8 que recorre todos los enlaces internos de inicio, una DCI y una ficha).
- Supabase caído o RPC con error → mensaje "La búsqueda no está disponible en este momento", sin excepción sin capturar (test en Task 4).
